## 현재 실행 환경

이 저장소에는 문서와 폴더 자리표시자만 있다.
`package.json`, lockfile, 앱 진입점, 실행·검증 스크립트는 아직 없다.
현재 단계에서 패키지를 설치하거나 개발 서버·앱 테스트를 실행하지 않는다.

## 후속 개발 세팅 순서

1. [선택한 Stoic Quotes와 번역 검토](quote-data.md)를 바탕으로 한국어 번역 경로·비용·이용 조건과 호출 구조를 결정한다.
2. 지원 중인 Node.js LTS와 npm, Vite 및 주요 라이브러리의 호환 버전을 확인한다.
3. 기존 README·문서·폴더를 덮어쓰지 않도록 React + TypeScript 프로젝트 설정을 통합한다.
4. 기본 CSS, ESLint, 타입 검사, Vitest + React Testing Library를 최소 구성으로 설정한다.
5. 의존성 lockfile을 추가하고 기존 `.gitignore`를 도구 구성에 맞게 보완하며 설치 버전·실제 명령을 문서화한다.
6. 기능 구현 이전의 최소 앱으로 개발 서버·빌드·검증 명령이 동작하는지 확인한다.

버전과 설정 파일은 이 단계에서 확정하며 지금 가상의 설정을 만들지 않는다.
개발 서버의 포트와 로컬 URL도 실제 구성 후 기록한다.

## 향후 스크립트 계약

아래는 개발 세팅 시 구성할 목표이며 **현재 실행 가능한 명령이 아니다.**
프로젝트 생성 후 실제 `package.json`과 일치하도록 갱신한다.

| 예정 명령 | 목적 |
|---|---|
| `npm run dev` | 로컬 개발 서버 |
| `npm run build` | 정적 배포 산출물 `dist` 생성 |
| `npm run preview` | 빌드 결과 로컬 확인 |
| `npm run lint` | ESLint 검사 |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run test -- --run` | Vitest 단일 실행 |

lockfile 생성 후 재현 가능한 설치에는 `npm ci`를 사용한다.
도구별 실제 옵션은 설치된 버전에 맞춰 검증한다.

## 코드와 테스트 배치

폴더별 책임은 [아키텍처](architecture.md)를 따른다.
상태와 컴포넌트는 필요한 만큼만 분리하고 단일 화면에 전역 상태나 라우터를 추가하지 않는다.
테스트는 대상 코드 옆의 `*.test.ts` 또는 `*.test.tsx`에 둔다.
외부 API의 실시간 가용성에 단위 테스트를 의존시키지 않고 응답을 모의한다.

기능 구현 시 [제품 기획의 상태 전환](product.md)에 집중해 테스트한다.
요청 중 중복 호출 방지, 실패 시 기존 명언 유지, 빈 응답과 재시도처럼
실제 동작을 검증하며 구현 내부 구조나 상수만 확인하는 테스트는 피한다.

## 환경변수와 비밀 관리

- Vite의 `VITE_*` 환경변수는 브라우저 번들에 공개된다. 비밀 API 키를 넣지 않는다.
- 비밀 키를 소스, 문서, 테스트 데이터, URL, 로그 또는 Git 기록에 남기지 않는다.
- `.env.example`에는 공개 명언 API 주소만 기록했다. Vite 앱 구현 시 이 변수를 읽도록 연결해야 한다.
  공개 설정 외에 비밀이 필요해지면 값 없는 예시 변수와 로컬 비밀 파일을 구분한다.
  실제 로컬 비밀 파일은 기존 `.gitignore`로 제외한다.
- `.gitignore`는 `.env`와 변형 파일, 로컬 `.npmrc`, 개인 키·인증서,
  Azure 로컬 설정·도구 상태를 제외한다. `.env.example`과 `.env.*.example`은
  추적 가능하므로 비밀 변수는 실제 값 없이 변수명·설명만 넣는다. 공개 엔드포인트는 기재 가능하다.
- `.gitignore`는 이미 추적된 파일이나 소스·문서에 직접 적힌 비밀을 보호하지 않는다.
  커밋 전 `git diff --cached`와 `git ls-files`를 확인하고,
  비밀이 노출되었다면 파일 제외만으로 끝내지 말고 해당 자격 증명을 폐기·교체한다.
- 서버 전용 인증이 필요하면 서버 경유 구조를 먼저 정하고 서버 환경에만 비밀을 둔다.
- CI 비밀은 GitHub Secrets, 서버 비밀은 해당 Azure 서비스 설정으로 관리한다.
  GitHub 배포 자격 증명과 외부 API 키는 목적과 저장 위치를 구분한다.

## 검증 원칙

현재 문서 단계에서는 내부 상대 링크, 파일 트리, 결정·미정 사항의 일관성을 확인한다.
문서 검사 도구가 없는 상태에서 이를 위해 패키지를 설치하지 않는다.
앱 구성 후에는 변경 범위에 맞는 테스트와 린트·타입 검사·빌드를 실행한다.
브라우저에서 키보드 조작, 좁은 화면, 로딩·실패 상태도 확인한다.

## Git 작업 규칙

작업 단위가 끝날 때 변경 범위를 확인하고 커밋·푸시한다.
Web/UI 구현부터는 기본 브랜치에서 분리한 작업 브랜치로 진행한다.
원격 저장소가 정해지지 않았다면 소유자·저장소명·공개 범위를 먼저 확인하며,
임의로 GitHub 저장소를 만들거나 공개하지 않는다.

커밋 전에는 관련 없는 변경과 비밀이 포함되지 않았는지 확인한다.
커밋에는 다음 공동 작성자 트레일러를 포함한다.

```text
Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>
```

원격이 없거나 인증이 준비되지 않아 푸시하지 못했다면 로컬 커밋과 푸시 상태를 구분해 보고한다.
